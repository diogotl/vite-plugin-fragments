# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

`vite-plugin-fragments`: a Vite plugin that replaces `<load src="..." />` tags in `index.html` with the contents of HTML fragment files, at build time and in dev. Fork of `donnikitos/vite-plugin-html-inject`.

## Layout

- `src/index.ts`: the whole plugin (single file).
- `test/index.test.ts`: Vitest suite. Tests run real Vite builds and a dev-server transform against temporary projects.
- `examples/basic/`: a small Vite project used for manual checks and a build test.
- `skills/vite-plugin-fragments/SKILL.md`: usage guide shipped in the npm package for agents of consumer projects.
- `README.md`: user-facing documentation. Keep it in sync with behaviour changes.
- `CHANGELOG.md`: generated by Changesets. Do not edit by hand.

## Commands

- `pnpm install`: install dependencies (pnpm, see `packageManager`).
- `pnpm test`: run the test suite.
- `pnpm lint`: Biome check. `pnpm format` applies fixes.
- `pnpm typecheck`: TypeScript check.
- `pnpm build`: build `dist/` with unbuild.
- `pnpm example`: dev server for `examples/basic`.

## Working rules

- Before committing, run `pnpm lint`, `pnpm typecheck` and `pnpm test`.
- Add or update a test for every behaviour change. Bug fixes need a test that fails without the fix.
- Commit directly on `master`. Do not create a branch per change unless asked.
- Commit messages use Conventional Commits, in English, one line, no body and no co-author trailers.
- Add a changeset (`pnpm changeset`) for user-visible changes.
- Do not publish to npm by hand. Releases are automated: pushing a changeset to `master` makes the Release workflow open a "chore: release" PR; merging it publishes to npm (trusted publishing), pushes the `vX.Y.Z` tag and creates the GitHub release.
- Keep TypeScript on 5.x. TypeScript 7 breaks `rollup-plugin-dts`, which `unbuild` uses for declaration files.

## Design notes

- Relative `./` and `../` sources resolve from the including file. Other sources resolve from the Vite `root`.
- Replacement values are inserted with function replacers, so `$&`, `` $` `` and `$'` stay literal.
- Circular includes are detected with the chain of files that led to the current one.
- HMR: the plugin registers `hotUpdate` (Vite 6+) and `handleHotUpdate` (Vite 5). Both send a full reload when an included file changes.
- The package is ESM only and declares Vite as a peer dependency.
- CI runs the tests on Vite 5, 6, 7 and 8. Vite 5 uses Vitest 3, because Vitest 5 requires Vite 6+.
